# field-vault

A Java experiment with field-level encryption: AES-256-GCM encryption of values, with data keys generated by AWS KMS, running against a local KMS emulator (LocalStack) in Docker.

## Why I built it

To learn the envelope-encryption pattern in Java: KMS holds a master key, hands out data keys, and the application encrypts fields with the data key. It follows on from [encrypt-migration](https://github.com/JasonTodd86/encrypt-migration).

## What it does

- `AesGcm`: encrypts and decrypts byte arrays with AES/GCM/NoPadding, using a random 12-byte IV per message and a 128-bit tag
- `KmsClientFactory`: builds an AWS SDK v2 `KmsClient` pointed at LocalStack (`localhost:4566`) with dummy `test`/`test` credentials and short timeouts
- JUnit tests check the round trip, that ciphertext does not contain the plaintext, that the same input gives different ciphertext each time, that tampered ciphertext is rejected, and that KMS generates an AES-256 data key

## Stack

Java 21, Maven, AWS SDK for Java v2 (KMS), JUnit 5, Docker Compose, LocalStack

## How to run

```bash
docker compose up -d     # starts LocalStack with only KMS enabled
mvn test
docker compose down
```

The `test`/`test` credentials are the dummy values LocalStack accepts; no real AWS account is used.
